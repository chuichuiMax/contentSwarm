# 行业策略包与可靠规则源改造

## 目标

把装修行业的全层级匹配总表从静态示例升级为可校验、可发布、可回滚的规则源；把“内容方向管理”升级为“行业策略包管理”，让同一套 Agent、Skill 和工作流通过配置适配其他行业。

## 边界与原则

- 生产任务不实时依赖飞书页面，仅读取已发布的本地规则快照。
- 飞书同步只创建或更新草稿，不能直接覆盖线上版本。
- 行业、内容方向、策略组、标题公式和正文公式都使用稳定 Code；显示名称可以修改。
- 原版公式和适配场景保存原文、来源修订号和内容哈希，运行时不得修改原版结构。
- Agent 只能在已发布行业包的候选边界内选择；行业业务规则放在版本化数据和 Skill 中，代码只实现通用契约与校验。
- 爆款按完整文章建档。运行时先做行业/方向/策略组硬过滤，再做确定性评分，禁止用零散段落冒充完整原文。
- 历史任务继续使用创建时冻结的规则、行业包、Skill 和爆款画像版本。

## 验收标准

1. 飞书源缺少公式、场景、稳定 Code、引用对象或组合成员时，草稿可以保存但不能发布。
2. 同步能显示新增、修改、删除和未变化项；发布后可回滚，历史任务不受新版本影响。
3. 新增一个非装修行业及内容方向不需要修改策略工作流代码。
4. 用户明确行业/方向时直接锁定；未明确时 Agent 可以评分选择，但不能跨行业或跨策略组。
5. 每次策略决策能追溯到行业包、规则版本、策略组、公式原文哈希、Skill 版本和候选得分。
6. 爆款匹配只返回完整文章，默认不跨行业；候选不足时按创作模式执行明确策略。
7. 运行节点有分阶段耗时，策略和爆款选择不再承担全文结构抽取。
8. 相关后端单元/集成测试、前端构建与关键内容生产 E2E 通过。

## 实现结果与验证

- 外部总表通过稳定 JSON 导出协议同步，生产运行不解析飞书页面；同步内容经规范化、引用完整性校验和 SHA-256 后保存为不可变快照，重复同步按哈希幂等。快照应用只创建规则草稿与行业包草稿。
- 装修 V3 保留 7 个内容方向、28 个完整组合组和 7 个黄金样例；新增教育行业规则源样例，证明新行业及其方向不需要修改工作流代码。
- V3.8 工作流升级为 26 个节点、27 条边，增加独立的确定性爆款评分节点；评分固定为可填充 30、场景 20、痛点/结果 15、受众 10、目标 10、标题公式 5、正文公式 5、渠道 5。
- 规则源、行业策略包、策略选择和爆款画像相关后端回归 922 项通过（1 项按环境条件跳过）；最终补充结果页审计字段后，内容域 840 项再次全部通过。
- 本次改动的 Python 文件通过 Ruff format/check，6 个内置 Skill 通过 `quick_validate.py`，前端定向 ESLint 与 Vite 生产构建通过。
- 本地浏览器在 `/content/admin/rules` 实际验证规则源与行业策略包 Tab：页面展示 12 个现有 V2/V3 包，装修 V3 为 7 个方向/28 个组合组/7 个黄金样例，教育 V3 为 7 个方向/7 个组合组/7 个黄金样例。

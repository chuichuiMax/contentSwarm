# contentSwarm 小程序后端整合（2026-09-29）

## 目标与范围

以 `chuichuiMax/contentSwarm` 的 `main` 为基底，接入现有小程序前端使用的图片设计、个人素材和作品接口，并使图片生成结果同时出现在 PC 素材库与小程序生图图库。保留目标仓库的内容生产、远程素材同步和 PC 现有行为。小程序前端继续留在 `chuichuiMax/ai-acquireCustomers`。

## 验收标准

- [ ] 小程序当前调用的 `/api/mp/image-design/*`、`/api/mp/content/my-materials/*` 和 `/api/mp/image/works*` 均已注册，认证与归属校验有效。
- [ ] 生成成功后结果资产、PC 素材项和小程序图库引用一致；重试不重复入库，隐藏小程序引用不删除 PC 原图。
- [ ] 固定保存位置按当前小程序与后端契约执行；旧草稿可兼容，失效目标在任务创建和 Worker 执行时都被拒绝。
- [ ] 新表与既有表字段可在目标数据库安全创建或补齐；历史素材只做 dry-run 预览，待人工复核后另行执行迁移。
- [ ] PC 现有内容生产、图片设计、远程素材同步及小程序原有登录和内容接口回归通过。
- [ ] 完成检查、相关单元与 API 测试、Lint，并在 Docker 中验证关键端到端流程。

## 合并约束

共享文件按目标仓库现状逐段融合；不整文件覆盖目标仓库的内容生产、员工认证、远程素材同步和封面生成实现。原工作区未提交内容不进入本次合并。

目标仓库仍将私人分类 `product` 用作“产品商品”。本地旧版 `migrate_default_image_galleries.py` 会把它迁为“AI 生图图库”并移走其他 PC 默认分类，与目标仓库的数据含义冲突；本次不纳入该脚本，也不执行其 `--apply`。小程序新增生成结果使用独立的企业“生图图库”，历史素材仅保留来源可判定的 dry-run 预检。

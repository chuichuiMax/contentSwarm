# Emoji 语义表达修正

## 目标与原因

装修案例已含痛点、面积、预算、工期、改造事项及互动，但原规则建议全篇 2～5 个 Emoji，导致只留下场景、确认与私信符号。仿写、排版和去机械腔规则又限制参考密度或强调克制，使情绪与信息导航容易在后续润色时丢失。

本次由 Agent 在现有生成调用内完成表达与自检，标准放在版本化 Skill 中，不新增 Emoji 数量硬编码、独立模型节点或前端随机插入。

## 开发点

- `content-human-expression` 2.0.0：按实际出现的痛点、人设判断、情感变化、数据类别、事项列表、提醒与互动逐项覆盖；不存在的功能不硬加。
- `viral-structure-rewriter` 1.6.0、`viral-layout-formatter` 1.6.0：参考密度不再是上限；保留冻结结构和列表类型，已有列表逐项导航，无列表时在原短语旁使用符号。
- `humanizer-zh` 1.2.0：保留功能型 Emoji，去掉的仅是无关和重复装饰。
- `content-body-generator` 2.3.0：移除“平台无关正文”对渠道排版的冲突；原创模式的并列事项在原结构块内逐项短行呈现，不回退成长段。
- `content-reviewer` 1.9.0：严格审核模式指出具体遗漏的语义位置，而非按三个表情判定通过；普通生成仍在同次调用内自检，不增加审核调用。
- 保留数字、单位、“预算”“预计”等事实限定词；专业人设不等于无表情，用户或渠道明确禁用时遵守禁用。

## 验收

- [x] 相关 Skill 与工作流单元检查：30 项通过。
- [x] 本地注册版本更新到上述版本。
- [x] 使用原装修任务的冻结输入隔离回放生成，检查情绪、数据与事项中的实际落点及原有事实校验。
- [x] 同一材料设为渠道禁用 Emoji，确认最终正文无 Emoji。

真实回放测试位于 `backend/test/e2e/test_emoji_expression_generation.py`，通过 `EMOJI_EVAL_SOURCE_NODE_ID` 显式指定已完成的装修生成节点。测试克隆任务、调用实际生成 Agent，随后归档隔离任务；不覆盖原稿，不生成封面，不发布。测试中数量只用于该特定夹具的回归信号，不作为跨行业产品标准。

## 最终实测结果

两个真实生成 Agent 回放均通过，保持原有节点与模型配置。允许表情时生成 13 个语义 Emoji，用时 35.51 秒；渠道禁用时为 0 个，用时 35.71 秒。两稿均通过原有确定性校验，未增加正文事实或放宽数字约束。

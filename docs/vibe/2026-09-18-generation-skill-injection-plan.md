# 仅爆款仿写的生成与审核 Skill 性能方案

日期：2026-09-18

状态：单体 v3 候选实现完成并保留为基线；运营规则需要长期按标题、正文、报价、平台表达、话题和视觉分别维护，后续实施由《爆款仿写模块化 Skill 与 Agent 实现计划》接续。默认入口保持现行仿写工作流。

## 已确认的范围与验收目标

- 后续内容生产只支持 `viral_rewrite`。原创模式的新建、继续运行、回修和历史原创任务操作能力均移除；数据库中的历史记录不因性能改造而删除。缺少可用的同类型、可填充爆款参考时明确失败，不转为原创。
- 优先保证爆款结构可辨识、事实和报价口径正确、首尾人设有据、Emoji 按语义覆盖、审核与定点回修有效。不能以缩短提示词为由放宽服务端校验或语义审核。
- 保持标题、大纲和正文同一次生成，保持现有独立审核节点，不增加模型调用、`read_file` 往返或额外润色节点。
- 量化目标是缩短有效提示词并争取减少生成节点耗时；最终放行取决于同模型成对回放的质量与时延结果，不能把字符减少直接当作时延收益。

## 当前链路与真正的基线

### 飞书创作文档与现有实现

[《装修工长 AI 小红书内容生成逻辑》](https://fycrbjmor5.feishu.cn/wiki/Cb5Kw0RI2i1N7lkn7oVcp00Injh) 是创作规则来源，定义内容生成因子、人设三层、标题公式、正文模式 A～I、场景与优势匹配、图片证据、真实性和第十四节的成稿验收。它的示例是写法示意，不能作为本次业务事实或直接复制到模型提示。文档强调抽取可复用结构并注入工长真实资料，正好对应当前仿写只借结构、不借参考原句与事实的边界。

项目已把这份文档标在 `foreman_rule_catalog_v1.json` 与 `body_calling.py` 的来源元数据中，规则快照经 `joint_strategy.py` 装入锁定方向蓝图、标题/正文公式及 `body_calling`；生成输入带 `content_brief`、词库、冻结证据、人设与渠道；服务端校验公式编码、段落顺序、词库调用、Evidence ID 和数字，审核 Skill 已逐项检查 Emoji、人设及创作类型组合。因此本次**不重做**创作类型、标题/正文公式、参考筛选或事实证据链，也不把飞书全文当作新的 Skill 注入。文档的图片识别要求需单独核对实际实现，不作为本次提示词性能改造的新功能。目标只是减少执行既有规则所需的重复指令，并修正被裁剪审核范围中的明确空缺。

代码中该文档的来源快照标为 2026-09-11，网页显示 9 月 16 日修改。当前不能断言两者逐条完全一致；实施前须对这五天的规则差异做一次对照，只有确认属于现有行为缺口的条目才另列业务改动，不能混进性能优化基线。

当前前端 `ContentStudioView` 已强制创建 `viral_rewrite`，但后端 `ContentTaskCreate.creation_mode` 仍默认 `original`，工作流、校验及 Skills 中仍有原创分支。因此只删提示词里的原创段落还不等于移除原创能力。

本次浏览器任务是原创，之前实测的六份 Skill 15,358 字符不能作为未来仿写的性能基线。仿写生成节点实际需要 **七份** Skill：标题、大纲、正文、`viral-structure-rewriter`、排版、中文自然化和有人味表达。按当前内置文件及现有排版 Skill 的仿写模式裁剪逻辑静态计算，七份有效正文合计约 **22,765 字符**；实际运行还需以事件中的 `applied_skills` 核验。默认语义审核使用 `expression` 范围，其审核 Skill 有效正文约 **2,952 字符**。

| 当前仿写生成 Skill | 有效字符（静态计算） | 主要冗余或风险 |
| --- | ---: | --- |
| 标题、大纲、正文 | 5,867 | 旧标题候选/选择节点、原创说明、重复的证据与公式边界 |
| 爆款结构仿写 | 5,326 | 结构映射、自检和 Emoji 规则多次复述；部分规则对首次与回修混用 |
| 仿写排版 | 3,233 | 与结构仿写、表达 Skill 重复叙述 Emoji 位置、列表与事实边界 |
| 中文自然化 | 1,448 | 通用长文改写说明与本节点规则同时注入 |
| 有人味表达 | 6,891 | 首尾人设、Emoji、禁词、回修和多轮自检同份常驻；约占七份总量的 30% |

当前还存在一个**质量缺口**：普通 `semantic_review` 只启用 `expression` 范围，明确检查 Emoji、人设和创作类型/组合；“标准单价参考不能写成本案成交/结算”等细致报价审核主要位于被裁掉的“完整审核”章节。服务端能校验来源、数字和部分结构，但不能仅凭数字白名单识别所有价格口径偷换。优化生成 Skill 时应一并修正审核范围，而不是继续假设审核已覆盖报价语义。

输入过长也不等于总耗时都来自输入。原任务首个输出进展约 3.34 秒，模型总调用约 30.74 秒，后续输出持续约 27 秒。仿写必须单独量出输入/输出 Token、首个输出、持续生成时间、回修调用和审核耗时，再判断收益来自哪里。

## 推荐方案

### 一、用一个专用仿写生成 Skill 取代七份拼接

为新工作流建立版本化的 `viral-content-author` Skill，替代七份旧生成 Skill 在 `generate_content` 的注入。它仍是正式 Skill：保留授权、安装版本、目录哈希、激活事件和本次有效指令哈希。旧内容生成 Skill 从新工作流的必需清单与生成 Agent 配置中移除；若仍被其他非内容 Agent 使用，只保留其通用用途，不把旧内容规则带回新流程。旧内容工作流和原创分支的代码/资源在引用审计后清理。

新 Skill 只写爆款仿写的一条执行顺序，避免七份 Skill 互相转述；公式内容仍以锁定快照为准，不在 Skill 重新维护飞书模式表：

1. 校验唯一选中参考与 `structure_fillability`；按锁定创作类型、标题公式、正文公式、方向蓝图建立标题槽位和正文信息块映射。
2. 用本次允许的 Evidence 填充事实；参考只提供标题模式、钩子、块顺序、节奏、列表、情绪和互动方式，绝不复制参考事实或原句。
3. 一次生成标题、大纲和正文，落实词库、`paragraph_evidence`、数字约束及真实价格口径。
4. 保留参考可感知结构，完成短段/列表排版、自然化、首尾人设和语义 Emoji，然后提交结构化结果。
5. 只做一次合并自检；若是回修调用，按现有阻断代码定点修改上一轮结果，不重写无关段落。

这不是把规则压成“写得自然、适量加表情”。下列规则在新 Skill 中仍需有可执行的具体表述：

| 质量边界 | 新 Skill 必须保留的内容 |
| --- | --- |
| 首尾人设 | 从当前人设和冻结证据取身份/经历/优势；首段贴合主题，末段用真实服务范围承接；用户禁止自述或营销、资料缺失时有明确例外；不得把案例城市写成服务城市或虚构亲历/承诺 |
| Emoji 语义覆盖 | 用户和渠道限制优先；按实际存在的痛点/判断、不同数据类别、独立事项、提醒和互动逐项检查；叙事与清单按参考分布，符号紧邻语义；不用固定数量、不拿项目符号冒充 Emoji、不为补符号编造内容 |
| 报价口径 | 明确区分标准单价、项目报价、预算和结算；保留地区、项目、单位、包含范围；标准单价可独立展示但不能冒充本案成交/结算；未经同源校验不得自行倒推工程量、小计或合计 |
| 爆款结构 | 标题槽位、开头钩子、`content_block_sequence`、`list_pattern`、`paragraph_rhythm`、情绪推进和 `interaction_style` 在成稿中可辨识；服从已锁定的创作类型和公式，不把具体样例特征套到每篇 |
| 定点回修 | 纯 Emoji 阻断只改 Emoji 和必要空格；首尾人设阻断保留未涉及的中段；事实/报价/结构阻断只修对应内容；所有阻断项复核后提交，维持两次模型调用上限 |

成稿评估除上述硬边界外，还逐项沿用飞书文档的可读性目标：标题仅一个主卖点且有搜索词，前两段有继续阅读理由，报价说明“怎么算、多少钱、包含什么”，每篇有明确用户价值，优势只选与场景匹配的 2～3 项，施工细节具体、CTA 自然且具体，不同工长的表达应随人设变化。这里用于回放和人工盲评；已有公式/策略规则不再造一套。

同一份 Skill 资源内区分“首次生成核心指令”和“按阻断代码选择的回修指令”。服务端按已校验输入确定性选择有效段落，不能让模型自行决定要读哪个文件，也不能用运行时模型总结 Skill。报价段只在存在价格证据或报价公式时加入；Emoji 禁用场景只放禁用规则。使用明确、可验证的段落标识与版本校验，避免继续依赖容易受标题变化影响的字符串截取。

首版把仿写生成有效指令控制在 **12,000～14,000 字符的设计预算**，相对静态基线约减少 39%～47%。这是待验证的预算；保留关键表达规则需要超过预算时，以质量为先，不删规则凑数字。先移除明显无关的旧/原创内容，再处理重复，最后才压缩高风险的人设和 Emoji 细节。

### 二、重写现有审核 Skill 的仿写范围，补上报价审核

保留当前独立 `semantic_review` 节点和一次审核模型调用。为该节点提供专门的仿写审核指令：继续逐项返回现有三项 Emoji 检查、三项人设检查及创作类型/组合检查；同时检查爆款结构可辨识、参考事实未移植，以及存在价格证据时的**价格类型、单位、地区、范围和“标准参考价/本案实际价”语义**。价格错用可沿现有 `FACT_INCONSISTENT` 阻断并定位原句，无须为每项规则新建一个审核调用。

服务端的公式、词库、Evidence ID、数字、金额空格、标题/段落锁定及回修文本校验继续作为硬门禁。审核检查必须针对最终成稿，阻断位置和建议应足够具体，避免生成 Agent 收到笼统的“重写全文”而多耗一次调用。审核 Skill 自身也删除原创/旧工作流说明，但不能通过扩大 `expression` 的名字来掩盖实际审核项缺失；运行事件记录实际审核范围和结果。

### 三、彻底移除原创模式的运行支持

新建任务的 API 契约只接受 `viral_rewrite`，不再默认为原创；工作流不再保留原创跳过参考、原创生成、原创校验及原创提示词裁剪分支。已存在的原创任务不再提供继续运行、回修或重新生成能力，API 返回明确的“不支持的创作模式”错误；不删除数据库记录和已生成资产。前端移除残余的原创模式假设和历史原创操作入口。清理前先盘点旧工作流版本与资源引用，避免误删仍被其他业务使用的通用 Skill。

## 实施顺序（评审通过后）

1. **固定仿写基线**：从真实冻结输入和事件采集七份有效指令、生成/审核的实际输入输出 Token（网关支持时）、缓存命中、首个输出、总耗时、二次调用率、阻断代码；补足当前观测盲区。
2. **建立规则对照与成稿样本**：逐条标记旧七份 Skill、审核 Skill 和服务端校验的规则归属；核对飞书 9 月 16 日网页与代码 9 月 11 日来源快照的差异；对首尾人设、Emoji、价格、参考结构、定点回修设置不可删除清单。
3. **实现新版 Skill 与审核**：版本化新 Skill 和有效段落选择，切换工作流/Agent 必需 Skill，强化同一审核调用中的价格语义检查；保持服务端硬校验。
4. **清理原创和旧规则**：收窄创建契约、移除原创执行/恢复分支与失去引用的内容 Skill；历史数据不迁移或删除，运行操作给明确错误。
5. **成对回放与灰度**：同模型、推理强度、输出预算与冻结输入比较旧七份和新 Skill；先通过质量门禁，再检查时延并分批发布。可通过版本化工作流回滚新 Skill，不用静默恢复原创能力。

## 质量和性能门禁

至少 30 份仿写冻结输入，覆盖多行业、不同爆款列表/节奏、有人设/无人设、Emoji 允许/限制、标准单价/项目报价/无报价、禁词表、首次生成及各类回修。每份基线与候选在相同模型配置下成对运行至少两轮；人工盲评至少 20 对成稿。

- **不可退化**：新增虚构事实、错用报价类型、无据人设、参考原文事实移植、漏掉核心结构、Emoji 禁用违规或定点回修改动锁定文本，任一出现都不放行。现有确定性校验和语义审核阈值不放宽。
- **质量对比**：逐项比较首尾人设、Emoji 语义覆盖、报价口径、爆款结构、自然度和可读性；记录首次通过率、审核阻断率、平均回修次数和人工盲评，不允许用更高重试率换取短提示词。
- **性能对比**：报告有效 Skill 字符和实际 Token、生成与审核各自的首个输出/完整耗时、额外调用率，以及从生成到审核和必要回修结束的总耗时。12,000～14,000 字符只是设计预算；目标为受控回放中生成节点中位耗时下降至少 15%、生成到审核的整段中位耗时下降至少 10%，P90 不明显恶化。若没有测到时延收益，应先定位输出与模型推理耗时，而不是继续删质量规则。
- **端到端**：Docker 下完成爆款仿写创建、参考冻结、生成、确定性校验、语义审核、必要回修和成品保存；验证原创创建及历史原创运行操作得到明确拒绝，历史数据未丢失。

## 评审结论

采用 **一个版本化仿写生成 Skill + 一个独立仿写审核 Skill** 取代七份生成 Skill 的长期拼接；原有六 Skill 的原创性能方案作废。质量门禁优先于字符预算和时延目标。

## 实施与验证记录（2026-09-18）

- 已新增 `content-workflow-blueprint-first-v3` 和两份专用 Skill/Agent。候选生成 Skill 按首次/回修、报价证据和 Emoji 禁用确定性选择段落；当前版本价格场景首次生成有效 Skill 为 5,421 字符，无价格为 4,998 字符，回修价格场景为 5,978 字符。旧七份静态基线为 22,765 字符；这是指令字符的变化，不能推算模型调用耗时。
- 新审核 Skill 实际注入 3,854 字符，保留八项 Emoji、人设、创作类型与组合检查，并在同次审核中检查参考结构、事实移植和报价类型。服务端确定性校验未放宽。
- 新建契约只接受 `viral_rewrite`；历史原创任务的生成、编辑、回修与续跑被拦截，已生成内容仍可只读查询。前端移除历史原创的编辑、复制和分发入口。
- 一份已冻结的真实仿写输入回放：候选生成仅调用模型一次，调用约 46.2 秒、首个输出约 8.9 秒，有效 Skill 为 5,285 字符，正文 438 字符，确定性校验通过；独立审核调用约 50.4 秒，返回八项必检项，并因“工种总价”公式缺少同一报价的各工种真实金额阻断。这是上游策略与事实不匹配，不能通过补写虚构报价让候选成稿通过，也不能将该样本计入质量通过率。
- 回放排除了两处无效重试来源：数字键帽 Emoji 曾被数字白名单误识别为无证据数字；过长正文曾通过结果工具却在下一节点才被阻断。现已忽略键帽中的导航数字，并把超过 650 字符的成稿拦在结果工具处给出精确纠错。普通无证据金额仍然阻断。
- 审核节点同样存在输入重复：报价样本的完整审核业务 payload 为 38,880 字符，其中简报 8,185、策略 7,127、证据 19,090。新候选审核只移除可从冻结证据复原的普通简报事实副本、重复方向/参考蓝图和审计元数据，保留用户原始请求、全文、全部事实 Evidence 和选中参考结构；当前投影为 31,070 字符，下降 20.1%。自荐样本投影为 29,453 → 15,913 字符，下降 46.0%。不同任务差异明显，不能把字符下降直接推断为审核耗时下降。
- 一份自荐型仿写的同输入初步对照：现行七份 Skill 实际注入 22,765 字符，生成模型调用 52.4 秒、首个进展 19.9 秒；候选单 Skill 约 5,000 字符，生成调用 41.7 秒、首个进展 7.0 秒。两版原稿均使用用户资料的“从业 5 年”，原确定性校验因原字段写作 `workYears=5` 而误判无来源；现在仅按 `manual_input` 的明确人设字段映射年/岁/工地数/推荐人数单位，金额和工期单位不互通，已存旧版原稿在新校验下通过。单样本、不同时间的模型调用不能证明 15% 中位收益。

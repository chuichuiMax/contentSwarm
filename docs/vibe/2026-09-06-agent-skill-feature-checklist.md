# Agent + Skill 功能开发清单

日期：2026-09-06。设计依据：[完整开发计划](2026-09-06-agent-skill-industry-strategy-development-plan.md)。

本清单记录实际落地状态；只有实现和对应验证均完成才勾选，后端基础完成不等于浏览器端到端通过。

## 已确认业务规则

- 装修：新蓝图优先入口不要求用户选方向，由 Agent 结合资料与参考卡自动采用内部方向，再在方向内选择标题、正文公式，不生成公式分数。旧任务保留原手动方向流程。
- 最新补充：[蓝图优先自动创作选择](2026-09-06-material-first-reference-matching.md)，合并资料判断与参考/公式选择，不增加独立模型调用。
- 其他行业：使用行业自身规则，对公式评分，不强制装修方向。
- 所有行业：独立评分选择创作手法；仿写时对爆款参考评分。
- 原文核验、参考卡及蓝图提前准备；在线联合决策后创作。
- Skill 管业务标准；代码负责工具、数据、执行、版本、权限和通用校验。

## 实现说明

- 正式 Skill 位于 `backend/package/yuxi/agents/skills/buildin/`；评分和行业路由位于 `content-strategy-planner/references/selection-policy.json`。
- 原文与准备结果按文章版本存储在 PostgreSQL，引用锚点严格对应该版本。Agent 给出唯一精确引用，工具定位坐标；重复/不匹配引用直接拒绝。
- 在线候选只传参考卡及必要事实槽位；蓝图按选中资产版本读取。首版文章召回采用权限与行业过滤后的词汇匹配，召回相关度不作为最终评分。
- 新工作流独立标识 `content-workflow-agent-skill-v1`，保留原有 V3.7/V3.8 定义和历史执行行为；本地 Docker 已发布新版本并切换六个行业模板默认入口；未部署云端。

## 已定位并修复的运行问题

1. 受管 Chatbot 创建模型时未传 reasoning_effort：现在使用 Agent 配置并有回归测试。
2. 外层 payload 路径导致重复提交：输入路径统一规范化后仍逐项核验真实字段，不放宽证据要求。
3. 候选同时带业务 code 和数据库 id：在线卡片只保留业务 code，避免模型误用数据库 id。
4. 辅助手法超出公式兼容范围：Skill 明确主手法与辅助项都遵守标题和正文的兼容交集。
5. 结果快照缺失：联合选择与锁定结果持久化，查询接口沿当前运行的恢复链读取已完成决策，不混入其他启动的数据。

6. 新参考决策接入旧创作证据契约时缺少用途标记和选择依据：锁定节点将已核验决策投影为完整创作证据，保留原评分、映射与蓝图；单元测试验证可通过实际证据汇总且不会引入原文业务事实。

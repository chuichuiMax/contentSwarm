# 内容生成模型输入性能优化

日期：2026-09-18

## 目标与范围

降低联合策略选择和正文生成节点的模型输入体积、推理延迟及重复调用风险，不改变锁定规则、冻结证据、输出契约和人工确认关口。本次聚焦模型可见视图；完整输入与审计快照继续由服务端保存并验证。

## 链路与基线

新任务的 Blueprint First v2 工作流依次装配策略候选，委派 `content-joint-strategy-agent` 执行 `select_creation_strategy`；必要时检索价格并复评，然后锁定策略、加载词库、并行补证、冻结证据，委派 `content-generation-agent` 执行 `generate_content`。策略 Agent 激活 `content-joint-strategy-selector`、`decoration-direction-formula-selector` 和 `industry-strategy-scorer`，仿写模式额外激活 `prepared-viral-reference-selector`。生成 Agent 激活 `content-title-generator`、`content-outline-builder`、`content-body-generator`、`viral-layout-formatter`、`humanizer-zh`、`content-human-expression`，仿写模式额外激活 `viral-structure-rewriter`。

2026-09-18 查询本地 Docker PostgreSQL 最近 14 天的节点记录：策略选择 11 次完成，平均节点时长 34.5 秒，3 次失败；生成 10 次完成，平均节点时长 53.7 秒。失败中 2 次用尽两次模型调用额度，1 次等待首个输出超过 65 秒。样本量较小，且包含不同任务与模型负载，不能当作 P95 或因果性能结论。

运行快照显示，策略候选在自动方向场景最高约 26.6 KB，其中 7 个方向蓝图约 12 KB；这些候选与逐项评价要求有关，不能仅为缩短提示而删除。生成视图中的锁定策略、证据和参考选择结果存在重复：方向蓝图在策略顶层、正文公式、正文调用契约中各保存一次；参考卡和选择审计既在策略快照中，也在选中的 `style_reference` 证据中；用户确认的手工字段有时同时出现在简报和证据中。

Skill 也是每次模型调用的固定输入：从当前源文件静态计数，生成 Agent 的 7 个 Skill 在仿写模式共 23,558 字符，原创模式排除仿写 Skill 后 6 个共 18,231 字符；实际注入时排版 Skill 还会按模式裁剪。这部分与业务 payload 分开计算，不能把下述 38.6% 当作完整模型提示的降幅。保留标题、正文、结构、排版和人设约束，避免为减少 Token 改坏内容验收规则。

## 改动与验收

- [x] 策略视图只在唯一自动方向的顶层蓝图与候选蓝图完全相同时移除副本；完整候选仍供服务端校验。
- [x] 生成视图保留一份方向蓝图、正文执行段落、完整事实证据和选中参考蓝图；移除审计哈希、重复参考快照、重复蓝图与参考候选比较记录。
- [x] 只合并“同来源、同变量、同类型、同值且已确认”的简报事实副本；不同口径的价格或布尔值继续保留。
- [x] 给模型输入策略版本加号，并补充投影契约单元测试。
- [x] Docker 内容域单元测试 1,113 项通过；装修方向集成检查通过。完整旧行业创建集成文件存在与当前显式类型持久化行为不符的断言，本次没有改写业务逻辑。
- [x] 原创真实 Worker 隔离链路通过内容审批：策略模型视图 31,322 → 27,158 字符，生成视图 23,541 → 13,958 字符；生成调用 2 次。
- [x] 仿写真实单节点冻结输入回放：生成视图 30,592 → 13,523 字符，首轮因两个无来源数字被确定性校验拦下，第二轮修正后通过。另一次完整仿写流程在报价补证节点因环境未授权价格库停止，未将该环境失败计作本次投影回归通过。

按同一批已完成运行快照，在容器内将旧、新投影序列化后比较：生成节点 10 份输入合计由 302,385 字符降至 185,735 字符，下降 38.6%；策略选择 7 份可比较输入由 232,795 降至 230,171 字符，下降 1.1%。这是模型业务 payload 的字符数，不包括 Skill、系统消息、工具 schema 和模型输出；实际时延改进须用同模型同负载重新测量。

对仿写样本尝试过额外的数字白名单提示，模型首轮仍重复生成无来源数量，因此未保留这项无效改动。现有确定性校验和有限回修能够拦截并修正，但它们是当前主要的额外模型调用来源之一。

浏览器真实任务暴露出一处额外回修来源：证据写作 `560 元`，生成正文写作 `560元` 时，数字白名单误判为无来源数字，模型随后删掉金额又被语义审核要求补回。现已在提取证据数字和校验正文数字时统一金额与单位之间的空格；单元测试覆盖合法 `560 元` 与非法 `999元`，并用失败任务的冻结证据回放确认误报消失。

另一条真实自我介绍任务显示，`FRB05` 原来强制把“落地背书”和“案例引导”词库全文送给模型，即使本次证据只有工长身份和做事方式。词库里的“按需改造不浪费”“同城户型改造”“想看工地实拍”被模型反复写入，语义审核连续要求删除，最终达到回修上限。自荐公式现仅调用与已提供做事优势相关的核心优势词库；案例或施工结果仍只能来自本次证据。词库选取测试覆盖该约束。同一简报的新任务模型可见输入由 11,033 降至 10,018 字符，正文一次通过 7 项语义检查，并完成封面和成品保存。

这次封面验收另发现系统视觉模板带有未声明为可填充字段的示例金额和户型；生成封面保留了这些原样图层。已在本次成品的编辑器中删除无关图层并保存新内容版本。系统模板的静态示例文字仍是后续任务的独立风险，需要在模板发布和选择环节修正，不能以本次正文输入优化的通过结果覆盖该问题。

## 风险边界

仿写仍从冻结 `style_reference` 证据读取完整结构蓝图和必要槽位可填充性，不能从旧版参考审计副本读取。服务端输出校验继续使用未裁剪输入，模型视图不能替代冻结策略 hash 校验。自动方向的多候选蓝图、公式、手法和评分权重继续完整发送，避免为了减少 Token 损害策略选择。

# Agent + Skill 行业策略与爆款资产开发计划

- 日期：2026-09-06。
- 状态：首版功能已实施并在本地 Docker 启用；原创、仿写、失败恢复与实际页面回归通过；业务质量和统计性能校准待后续执行。实际状态见 [功能清单](2026-09-06-agent-skill-feature-checklist.md)。
- 目标：业务选择规则由 Agent + Skill 执行，装修按用户选择的一级内容方向选公式，其他行业按输入评分；通过提前准备爆款参考资产减少在线耗时。
- 适用工程：Yuxi / ContentSwarm 内容创作链路。
- 文档关系：本计划替代 `2026-09-05-agent-skill-strategy-and-viral-selection.md` 中与本计划冲突的设计与验收口径；旧文档保留作为历史记录，其已勾选事项不代表当前检出版本已实现。

## 1. 已确认需求与范围

### 1.1 行业分支

| 决策对象 | 装修行业 | 其他行业 |
| --- | --- | --- |
| 一级内容方向 | 使用用户明确选择的方向，Agent 不自动改选 | 不强制装修的方向层级或 CT01—CT07 枚举；已有行业分类按自身配置使用 |
| 标题公式 | 仅在该方向绑定的有效候选内选择，不做数值评分 | 在该行业有效候选内逐项评分 |
| 正文公式 | 仅在该方向绑定的有效候选内选择，不做数值评分 | 在该行业有效候选内逐项评分 |
| 创作手法 | 根据本次输入独立评分 | 根据本次输入独立评分 |
| 爆款参考 | 根据本次输入及选定策略评分 | 根据本次输入及选定策略评分 |

装修方向内只有一个满足资料要求的合法公式配对时直接采用；有多个时，由 Agent 按适用说明匹配并解释，不默认选择配置首项。方向缺失、公式候选为空、必要事实缺失或无兼容配对时，明确返回问题，不跨方向选择。

### 1.2 必须解决的问题

1. 公式选择不能再由数组顺序或固定组合组首项决定。
2. 手法不能再整组照搬，组合组仅保留来源、推荐信息及明确的兼容约束。
3. 爆款候选必须指向可核验的完整文章，不能将知识库片段当成原文。
4. 需要评分的对象必须有分项得分和证据；装修公式只保留选择理由与合法性检查。
5. 在线不再重复执行完整原文核验和复杂蓝图解析。
6. 不允许以自动跨行业、跨方向、转原创、填造事实或无限重试掩盖失败。

### 1.3 本期边界

本期覆盖 Skill、规则资源、资产准备、联合决策接入、结果展示、历史兼容和验证。复用现有队列、知识库、权限、模型运行时和审核流程，不建设新的通用工作流编辑器、独立向量平台或自动训练系统，不扩展封面生成业务。

业务规则不写进选择函数；允许必要工程接入。代码负责权限、契约、工具、运行状态、配置引用、版本锁定及通用校验，不内置行业评分权重或替 Agent 挑选首项。

## 3. 目标架构与真实运行链路

### 3.1 离线资产准备

原文入库或更新 → 爆款资产准备 Agent → 完整性与来源核验 → 参考卡及蓝图生成 → 一致性核验 → 发布可检索资产。

这是异步入库任务，不占在线创作的关键路径。同一原文版本仅在首次处理、失败后明确重试或相关 Skill 版本要求重建时处理。

### 3.2 在线主流程

输入与已有事实规范化 → 联合策略决策 Agent（读取行业规则、检索参考卡、选择公式与手法、选择参考）→ 通用校验与策略锁定 → 创作 Agent。

装修分支：用户已选方向 → 方向内公式匹配 + 手法评分 → 参考评分。

其他行业分支：行业候选硬过滤 → 手法与公式评分 → 参考评分。

原创模式跳过参考检索、参考评分和蓝图读取；正常使用公式和本次事实创作。

### 3.3 保留现有事实与审核依赖

“两个主要在线 Agent 阶段”仅指策略/参考决策和正文生成，不代表整个系统只调用两次模型。现有业务规则、价格、合规研究、人工确认和内容审核仍按需要执行。

实施第一版采用以下明确依赖，避免策略与证据循环等待：

1. 联合决策以用户输入及已经确认的当前项目证据判断必要事实槽位，不预支尚未取得的证据。
2. 策略锁定后加载公式词库，现有业务、价格、合规研究节点按已锁定策略执行；独立研究节点继续并行。
3. 研究结果汇合，经必要的高风险事实确认后冻结证据，再生成正文。
4. 普通业务资料不能被当成当前项目完工、结算等事实；若后续证据与策略冲突，返回明确缺口，不在生成阶段静默换式。
5. 用户补充或更改影响策略的事实后产生新输入版本，重新决策；不沿用旧输入的选择快照。
6. 保留现有内容确认、封面选择等人工节点，性能统计单独记录人工等待。

## 4. Agent 与 Skill 交付

| Agent | 时机 | 读取 | 输出 | 任务边界 |
| --- | --- | --- | --- | --- |
| 爆款资产准备 Agent | 入库、更新、明确重建 | 原文、来源信息、准备 Skill | 参考卡、蓝图、核验记录或缺口 | 不针对某次创作选公式、不补造原文 |
| 联合策略决策 Agent | 每次创作 | 输入快照、行业策略配置、规则卡、少量参考卡 | 行业分支决策、评分记录、参考 ID 与版本、槽位映射 | 不生成正文、不重抽蓝图、不阅读多篇完整原文 |
| 创作 Agent | 锁定及证据冻结后 | 公式、手法、蓝图、可用事实 | 标题、正文等既有结果 | 不重新检索、评分或换参考 |

正式 Skill 位于 `backend/package/yuxi/agents/skills/buildin`，不修改运行卷中的临时副本作为正式交付。

| Skill | 计划动作 | 内容 |
| --- | --- | --- |
| `content-strategy-planner` | 调整 | 联合决策总步骤、行业策略路由、输出边界；不重复内嵌各分支量表 |
| `decoration-direction-formula-selector` | 新增（拟名） | 使用用户方向、方向内选式、禁止数值评分及跨方向选择 |
| `industry-strategy-scorer` | 新增（拟名） | 非装修公式评分，以及各行业通用的独立手法评分 |
| `viral-asset-preparer` | 新增（拟名） | 原文核验、文章边界、参考卡、必要槽位、蓝图、一致性检查 |
| `viral-candidate-researcher` | 调整 | 检索已发布文章级参考卡、去重、候选上限与补检索边界 |
| `viral-reference-selector` | 精简 | 对候选卡评分并选择引用，不再输出详细蓝图 |
| 现有标题、正文、仿写及排版 Skills | 调整 | 消费锁定创作包，保持模板结构、事实与样式引用边界 |

每份 Skill 配套少量 `references` 规则资源：步骤、评分锚点、必要事实要求、兼容规则、正反例及输出样例。无需为每个量表再建一个 Agent，也不新增运行时循环审核 Agent。

行业配置声明策略模式、Skill 引用及规则版本：装修为 `direction_scoped`，其他行业为 `scored`。运行层通用分发并校验配置；模型不得自行改模式。权重、最低分及淘汰口径以版本化 Skill 资源为唯一标准，避免代码和提示词各维护一份。

## 5. 规则候选与评分设计

### 5.1 装修方向候选整理

从当前正式规则版本读取所选方向的有效标题/正文公式引用，去重后构成方向候选池。保留每个引用的来源，排除停用项；不能先选一个组合组再取其首项。

现有组合矩阵中的明示禁配与允许配对需要在迁移时区分：只有明确的兼容限制继续约束配对，不能把展示顺序、推荐组合或手法成员数误当成新硬限制。不得通过简单合并候选而丢失已确认禁配。

多个合法配对由 Agent 按输入适用性选择并给出短理由；不生成总分、名次分或将旧顺序包装成评分。

### 5.2 其他行业候选

候选从当前行业授权、启用、版本一致的规则中取得；不强制绑定装修方向，也不强制沿用某组合组全部手法。已有跨行业公式应用说明可复用，但必须核对行业归属和变量要求。

规则数量小时评价全部合格候选。数量过大时先按可解释的硬条件过滤，再按 Skill 的候选预算分批获取；记录检索/过滤范围、未评估数量和原因，不能声称对未读取的全集评分。首批试点控制规则规模，不引入无限候选遍历。

### 5.3 评分量表（待样例校准的 v1 初稿）

| 对象 | 维度权重，总和为 100 |
| --- | --- |
| 创作手法 | 目标匹配 30，素材适配 25，受众场景 20，渠道表达 15，人设语气 10 |
| 非装修标题/正文公式 | 核心信息适配 30，目标匹配 25，受众场景 20，渠道适配 15，人设语气 10 |
| 爆款参考 | 当前输入适配 30，受众场景 25，内容目标 20，锁定策略兼容 15，渠道表达 10 |

各维度 0—4 分，锚点为：0 无支持或冲突，1 仅宽泛关联，2 部分直接支持，3 大部分直接支持，4 直接充分支持。每个维度还须提供业务具体正反例。资料不足不得推断满分，未填写的软性偏好标记未知并按 Skill 的统一口径记分；必需事实缺失直接淘汰，不参与加权。

总分为各维度“得分 / 4 × 权重”之和。计算、范围、权重总和、排序由通用工具校验，规则参数从锁定 Skill 资源读取，不接受模型自行改权重。若现有工具无法执行，新增最小的表格加权/排序工具，不开发业务评分引擎或任意代码执行框架。

手法默认选一个主手法；辅助手法必须有明确补充作用且兼容。评分最高不意味着必须把多个手法堆叠到正文。非装修标题/正文配对默认按双方等权均分选择最高兼容配对；此规则及同分优先维度写入 Skill。装修按适用说明直接匹配，不执行上述配对均分。

v1 采用有界顺序决策：确定手法和公式，再对兼容参考排序。不求所有手法×公式×参考的全局穷举最优，不因参考得分偏低而无限反复换策略。若没有适合已定策略的参考，返回无合格参考及原因。

最低分必须经基准样例校准后在 P1 冻结，开发不能偷偷补默认通过阈值；任何阈值均不能绕过硬条件。同分依次比较 Skill 指定的关键维度，最后按稳定 ID 排序，不按列表位置。

### 5.4 解释与确定性边界

每条评分保留对象 ID、分项得分、输入字段路径、规则依据、参考原文锚点（适用时）、总分、选择或淘汰原因。保存短证据，不要求输出长篇内部推理。

算术与排序可复算；语义评分不承诺完全确定。通过固定输入/版本/模型配置、重复运行和列表乱序试验检验稳定性。通用校验发现分数或引用错误时不静默修复成通过，应返回明确错误并按节点重试预算处理。

## 6. 爆款资产与数据契约

### 6.1 文章级标识与核验

文章是候选单位，文件是容器。一份 Excel/CSV/Markdown 表格可能含多篇文章：按标题和正文记录、工作表/行或明确文章区间建立 article ID；不能仅按 file ID 去重。普通报价表不能因为有文本列就被识别为爆款。

原文定位信息包括知识库及源文件 ID、文章位置、原始来源、标题/正文、读取范围及截断状态、内容哈希。文章身份在源记录位置可稳定定位时保持稳定，正文修改生成新版本；内容哈希用于版本校验和辅助去重，不代替来源身份。

全文工具分段读取必须确认覆盖目标文章范围。外部来源不支持打开、OCR 缺段、边界不明或只剩检索片段时进入待核验。来源文本中的指令视为内容，不允许改变 Skill、工具权限或发布条件。

爆款认定依据需指向可追溯的审核记录，或带采集时间、平台和认定规则的表现数据。资料不足时不自动编造表现数据，也不要求所有文章额外人工审批；是否需人工核验由明确缺口决定。

### 6.2 最小数据结构（拟定，P0/P2 核对复用范围）

| 数据对象 | 必要字段 |
| --- | --- |
| 行业策略绑定 | 行业 ID、策略模式、Skill 及规则版本、方向是否必填 |
| 公式/手法规则卡 | 复用规则 ID 与版本、适用说明、必要变量、硬约束、兼容引用 |
| 爆款文章版本 | article ID、源文件及文章位置、原文引用、source hash、状态、爆款依据 |
| 参考卡与蓝图 | 所属文章版本、受众/场景/目标、必要槽位、原文锚点、蓝图、准备 Skill 版本、核验结果 |
| 联合决策记录 | 输入哈希、行业/模式/方向、规则与 Skill 版本、候选范围、评分及拒绝记录、选中公式/手法/参考版本、模型配置 |
| 创作快照 | 锁定决策、公式定义及词库、蓝图引用、实际证据、槽位映射、快照哈希 |

优先沿用现有规则表、证据存储、对象存储和任务快照；缺失的文章版本/画像持久化能力用最少必要模型补齐，不逐对象机械创建一张表。全文放现有文件/对象资源，数据库保留索引和版本信息。

资产状态：待处理、待核验、可用、失效。只有可用资产能进入新任务。更新期间新版本未通过前不将其标为可用；原文更正/撤回导致旧版本失效时，新任务不得选择旧版。

### 6.3 契约演进

新增版本化联合决策输入/输出和策略快照，名称在实施时统一注册，不直接放宽历史 V1 的行为：

- 行业模式来自冻结配置；装修方向必填，其他行业方向可为空或为行业自己的标识。
- 不要求所有新结果提交 `selected_group_id`；组合来源可作为审计字段。
- 装修公式分数不适用，不能用 0 或假分数占位；非装修公式需完整评分记录。
- 手法和仿写参考评分适用于两种行业模式。
- 参考结果只提交候选 ID、已发布版本、评分和槽位映射；服务校验并读取对应蓝图，Agent 不重写蓝图。
- 明确区分成功、需补充输入、无合格候选和执行错误；禁止缺少蓝图却标记仿写可生成。
- 原创模式参考与蓝图为空是合法分支，不能伪造占位候选。

预览与正式执行共用候选权限及版本口径。若预览已产生符合条件的锁定决策，可按相同输入和版本复用；输入、规则或 Skill 变化则使其失效，不能预览一套、运行再按首项选另一套。

## 7. 在线上下文、性能与恢复

### 7.1 控制输入和工具往返

- 候选卡初始上限 5，目标通常为 3—5 个，按文章去重；参考召回先使用输入、行业及装修方向，向量分数只作召回信号。
- 最多首轮检索加一轮有明确新条件的补检索；无候选时立即返回，不触发在线原文补建。
- 联合决策只读取规则卡及必要参考信息；选中后才由工具装配完整蓝图给创作节点。
- 规则库读取尽量批量完成，评分表只输出必要字段。上下文预算以不截掉关键约束为前提，具体 token 与超时配置根据 P0/P5 实测冻结。
- 不以单纯增加 75 秒超时值作为性能修复，不把旧 10/3/10/60 秒口径当成已验证指标。

### 7.2 版本与失败恢复

资产准备按来源、文章版本和准备 Skill 版本去重入队；失败重试不产生重复发布资产，发布前校验版本未被更新。

联合决策完整提交并校验后形成持久快照。创作失败只重试创作；研究节点失败只重试失败节点，复用已完成输出。工具调用中间消息不冒充已完成决策。输入变化需新建决策，不能借重试沿用过期评分。

正式资产失效或访问权限被撤销后，即使旧快照有引用也要按现有访问政策检查，不能以版本锁定绕过权限。对已生成历史结果保留来源记录，不悄悄改写历史原文。

### 7.3 指标与建议目标

记录用户提交到可审核正文完成的端到端时间，并分解：排队、规则读取、检索、联合决策、事实研究、生成、自动审核、重试。人工等待单独列出；首 token 时间单列，不代替完成时间。资产准备耗时和成本另列，避免隐藏首次使用成本。

首轮建议目标：在相同模型、输入长度和负载条件下，P95 端到端耗时较基线降低至少 30%，超时率不升高，关键质量指标不下降。该值是待基线验证的验收提案，不是已实现性能承诺。P0 明确冻结最终目标；不能为过性能线缩减必要质量检查。

## 9. 分阶段开发排期

以下为一名熟悉项目的开发者顺序实施的粗估，共 12—17 个工作日；不含外部模型不可用、来源材料补齐、大批量历史处理等待及额外审批时间。实际排期在 P0 完成后校准，不意味着现在开始实施或部署。

| 阶段 | 估时 | 任务与交付 | 完成门槛 |
| --- | --- | --- | --- |
| P0：基线与样例 | 1 天 | 确认当前实际工作流、规则数据和未提交改动；建立行业样例、完整原文样例、超时基线；确认装修方向映射和显式配对约束 | 当前数据来源、待迁移规则、质量样例与性能目标有记录 |
| P1：Skill 与契约 | 2—3 天 | 编写正式 Skills 与规则卡样例；定义行业模式、新决策契约、计分校验；校准并冻结 v1 权重/阈值 | 装修无公式评分，其他行业有评分；固定样例能产生合法结果 |
| P2：资产准备 | 3—4 天 | 文章级提取、异步准备 Agent、卡片/蓝图/核验、持久化及发布；先处理一小批各类型来源 | 多篇同文件正确拆分，缺失原文阻断，可用资产可检索且可追溯 |
| P3：在线工作流 | 3—4 天 | 联合决策接入、模式路由、候选检索、锁定及蓝图引用、词库与事实研究接续、重试兼容 | 两行业×两创作模式贯通，不运行在线蓝图解析 |
| P4：界面与迁移 | 1—2 天 | 输入与结果展示、管理员状态、历史资产分批补建、预览一致性、新旧工作流版本隔离 | 浏览器能完成方向选择、查看公式及参考原文；历史任务可读可恢复 |
| P5：回归与验收 | 2—3 天 | Docker 测试、Lint、真实模型评估、性能对比、灰度与回滚演练记录 | 质量门槛通过，耗时有可复现证据，未通过项明确阻断发布 |

每阶段交付最小可验证切片，不先做大规模数据导入或全站重构。现已在本地 Docker 发布独立工作流并切换六行业默认入口；云端发布另行执行。

## 10. 测试与验收矩阵

遵循 `docs/develop-guides/testing-guidelines.md`；测试位于 `backend/test/unit`、`integration`、`e2e`，通过 Docker 环境运行。固定契约测试与真实模型质量评估分别报告，不能以 Skill 文本包含某个关键词代替行为验收。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| D01 | 装修明确选择一个方向 | 标题和正文都属于该方向有效候选，无公式数值评分 |
| D02 | 装修方向未选/候选全部停用 | 返回补选或配置缺口，不自动选方向、不跨方向 |
| D03 | 方向内多个公式，打乱配置顺序 | 不呈现系统性的首项偏置，理由对应本次输入 |
| D04 | 方向内明示禁配或必需事实缺失 | 拒绝不兼容配对，不能用推荐顺序绕过 |
| I01 | 至少两个非装修行业、无 CT 方向 | 正常评分并完成策略选择，不要求装修方向或组合组 |
| I02 | 非装修候选混入装修专属或其他版本 ID | 通用权限/版本校验拒绝，不接受模型越界 |
| M01 | 独立手法与旧组合成员不一致 | 合法且兼容的独立手法可入选，不能整组强制覆盖 |
| M02 | 输入只有方案却要求实际完工结果 | 淘汰依赖已发生事实的手法、公式和参考 |
| A01 | 同一表格含多篇文章，同文命中多片段 | 逐篇建立 ID；同篇去重，多篇不因相同 file ID 合并 |
| A02 | 原文截断、边界不明、来源不可读、身份依据不足 | 待核验，不进入正式候选池 |
| A03 | 原文更新、重复入队、权限撤销 | 版本准确、无重复发布，权限检查不被快照绕过 |
| A04 | 蓝图增加了原文没有的列表或遗漏关键结构 | 核验失败，不发布该版本 |
| S01 | 分数越界、计算错误、伪造输入路径 | 校验失败，不能静默选择首项 |
| S02 | 相同分数或候选全部不合格 | 按 Skill 同分规则或明确无合格候选处理；首版未设未经校准的最低总分阈值 |
| W01 | 装修/其他行业 × 原创/仿写 | 四条路径完成；原创无参考调用，仿写只用已发布蓝图 |
| W02 | 全部参考不适合或资产未准备 | 返回缺口，不自动转原创或临时重建全文 |
| W03 | 创作失败重试，随后用户改变输入 | 前者复用决策，后者生成新决策；已完成节点不无故重跑 |
| W04 | 事实研究、高风险确认、正文审核及词库 | 现有能力未被性能优化绕过；参考中的事实不污染业务事实 |
| U01 | 规则库预览与实际生成、历史结果查看 | 候选/版本口径一致；装修显示理由，其他行业显示分数；原文页签可读 |

优先扩展已有 `test_content_v3_node_contracts.py`、`test_content_v3_workflow_definition.py`、`test_content_v3_formula_selector.py`、`test_worker_retry.py`、行业规则及原文视图测试；新增资产准备、联合决策测试按分层落位。

### 10.1 后续业务质量校准（尚未执行）

业务扩大使用前建立至少 30 个输入：装修原创、装修仿写、两个非装修行业的原创/仿写，共六类，各不少于 5 个，覆盖缺失事实、无候选和多候选。每个样例由规则维护者给出可接受选择集合和硬性拒绝项，不要求语义等价候选只能有唯一答案。

代表性歧义样例至少重复 5 次并随机调整候选顺序，记录选中项、合格集合命中率和分数波动。硬约束、来源及模式隔离要求全部通过；语义合格率建议至少 95%，并不低于基线，具体门槛 P0 冻结。低于门槛修订 Skill 再复测，不用增加硬编码选择补丁。

### 10.2 后续统计性能对比（尚未执行）

新旧版本使用相同输入、模型及并发设置，分开记录冷/热缓存；至少 100 个可比运行用于观察 P50/P95，样本不足时明确标为初步结果。失败与超时计入总体报告，不能只统计成功任务。关键对比包含原先 75 秒超时案例。

浏览器验收从实际 ContentStudio 入口开始，检查输入、运行状态、公式/手法结果、爆款原文、生成正文和重试。服务健康、单接口 200、构建成功均不能代替该验收。

## 12. 迁移、灰度与回滚

1. 使用增量数据/契约迁移，不删除旧组合矩阵、规则原文或任务快照。保留管理员草稿与已发布版本。
2. 为新工作流设置独立版本；新任务显式绑定新版本，运行中的旧任务继续使用其原有契约和节点定义。历史 V1 的读取/恢复能力保留在版本边界，不成为新任务失败后的隐藏回退。
3. 先对小批可核验原文补建资产并检查卡片/蓝图质量，再分批扩展。记录待核验与失败列表，不要求一口气处理全部历史材料。
4. 灰度按测试环境、受控任务范围、正式新任务逐步扩大；观察来源问题、行业串用、模型错误和真实延迟。
5. 回滚只切换后续新任务的工作流绑定；已完成快照与新资产保留，运行中任务按原版本完成或明确取消，不强制降级契约，不清理历史数据。
6. 发布前完成授权范围内的验证；本计划文档交付不代表生产发布已获执行或已完成。

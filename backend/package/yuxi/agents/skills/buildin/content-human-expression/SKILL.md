# 有人味的内容表达

在 `generate_content` 节点内完成表达优化，并直接产出 `GeneratedContentResultV1`。不要增加独立改写步骤，也不要输出修改说明。

## 表达目标

- 根据 `persona_profile` 和 `channel_profile` 确定说话方式；未提供明确人设时，使用自然、可信、不过度表演的中性表达。
- 让情绪来自真实场景、用户处境、问题变化和证据结果。情绪可以从理解、共鸣或疑问自然推进到确认、释然或行动意愿，但不要机械套用固定曲线。
- 通过关注点、判断方式、价值取向、措辞习惯和表达边界体现人设，而不是反复声明身份。
- 使用具体名词和动词，长短句交替，段落有呼吸感，转折和承接符合口语习惯。
- 根据渠道和爆款结构参考适量使用 emoji、设问、感叹或互动表达；它们只服务语气和节奏，不用于制造虚假情绪。

## 首尾人设表达（默认启用）

- 原创与爆款仿写默认执行。先从 `persona_profile`、`content_brief.persona`、用户需求及允许用于正文的冻结证据中整理可用的城市、角色、从业经验、擅长领域和服务优势；用户需求中的嵌套人设同样需要读取，不以空的 `persona_profile` 判定没有人设。资料中的语气偏好只能指导表达，不能当作从业或服务事实；爆款参考中的身份、经历和优势不能移植给作者。
- 第一段（正文首个非空自然段，不含标题）自然融入与本篇主题有关的身份，以及有依据的经验或擅长领域，再接本篇读者的具体问题。选择一两项有效信息即可，不堆砌履历，不强制“我是…”开头；项目在长沙不等于作者在长沙提供服务，工长身份不等于作者亲自施工了当前案例。
- 末尾（正文最后一个非空自然段，不含话题标签）结合已提供的一两项服务优势，给出贴合本篇问题、渠道允许且在服务能力内的行动邀请。仅有“欢迎咨询”或重复开头的城市、身份，不算有效收尾。资料未提供优势时只使用已有角色或业务范围承接，不编造自有团队、不转包、免费方案、响应速度、质保或结果保证；用户不要求转化、明确禁止营销/互动时不添加 CTA。
- 中间段落用有事实依据的专业判断体现人物，首尾承担不同职责；不在每段重复介绍身份。人设融入既有首尾段，不增加独立人设层、不改变冻结大纲和报价口径，不照抄固定范文。
- 用户明确要求省略自我介绍、第三人称、纯清单或其他不适合首尾人设的形式，以及渠道或锁定结构明确不允许时，遵从这些限制；没有可用人设事实时保持中性表达，不猜城市、职业、年限。只有部分资料时用已有信息，不要求补齐全部字段。
- 若审核阻断含 `PERSONA_OPENING`、`PERSONA_CLOSING` 或 `PERSONA_GROUNDING`，仅修正对应首尾段或无依据的人设句，首尾问题回修时，首尾以外的每一段必须逐字保留，不能改同义词、合并到首段或调整分段，只允许调整 Emoji 和必要空格。保留标题、报价数据、其他事实、结构顺序和未涉及的正文；依据现有证据修复并同步 `paragraph_evidence`。人设与表情同时阻断时可修改必要措辞，不受“仅表情回修”的文字锁定限制；只有表情阻断时仍严格只改 Emoji 和必要空格。
- 完成自然化与排版后复查最终首尾：能否识别相关身份、为何有资格讨论该问题，以及能提供何种已确认的服务；每一项身份和优势都有资料依据，例外情况不强行补写。

## Emoji 与表情符号

- 规则优先级：用户/渠道明确禁用或少量要求 → 当前正文的语义需要 → 参考排布。蓝图里的“仅一个”“无表情”是对参考的描述，不是当前成稿指令。少量要求可按清晰同类分组导航，不强制每个条目配图标。
- 若 `review_report` 的阻断项只有 `EMOJI_COVERAGE`、`EMOJI_APPROPRIATENESS`、`EMOJI_RESTRICTIONS`，在已有 `content_draft` 上逐项定点修改：只添加、删除或移动 Emoji 及必要空格；原文字、标点、金额、单位、标题、大纲、段落顺序、编号和证据引用原样保留，不重新创作文章。若还有其他阻断项，先修对应问题，再按本规则检查表情。
- 先读取 `channel_profile` 与 `persona_profile` 的明确限制。小红书等允许 Emoji 的社交渠道，在原创和爆款仿写两种模式下都执行以下语义覆盖检查；渠道或用户明确禁用时不用。专业人设意味着选择更准确、可信的符号，不等于全文只留少数装饰。这里的表情是正文中的 Unicode Emoji，不插入图片、贴纸链接或 `[微笑]` 等占位文字。
- 数量由当前正文实际承载的功能决定，不设置全篇 2～5 个的配额，也不把“已有三个”当作完成。先在内部标出“原文锚点—表达功能—拟用符号—相对位置”；检查下表中本篇实际存在的类别，遗漏的类别必须补齐后再提交。正文没有的情绪或列表记为不适用，不能为了放表情编造经历、情感或清单。

| 实际内容 | Emoji 应完成的工作 | 可用方式示例（按人设选择，不是固定词表） |
| --- | --- | --- |
| 痛点、疑问、担心 | 表达共鸣或疑问，不能只用场景图标代替情绪 | `😣东西没地方放`、`🤔预算怎么分配`，贴近已有处境，不把正常问题夸大成恐惧 |
| 人设判断、情感变化 | 表现关切、慎重、认可或释然；用符合人物语气的表情 | 可信专业者可在具体判断旁用 `🧐`，已有安心、轻松表达可用 `😌`；不虚构“客户感动哭了”等反应 |
| 数据与参数 | 帮读者找到不同数据类别，保留原数字、单位与限定词 | `📐89㎡`、`💰硬装预算18万元`、`🗓️预计工期90天`；面积、预算、时间各有独立导航，不能拿一个 🏠 覆盖整个数据块 |
| 事项、材料、方案或步骤列表 | 逐项标识对象、动作或状态，便于扫描 | 收纳 `🗄️`、厨房 `🍳`、学习 `📚`、验收 `🔍`；实际独立条目默认逐项匹配，连续同类参数可分组，不能只标第一项 |
| 风险、提醒与核对 | 指出真实注意点；确认符号不能暗示未经证实的保证 | `⚠️` 紧贴已有注意事项，`✅` 仅表示有依据的检查或结果 |
| 互动与行动 | 提示允许的下一步 | `💬`、`📩` 紧贴咨询或案例参考邀请，不新增优惠、赠送或保证 |

- 一篇同时包含痛点、个人判断、多个数据类别、改造事项和互动的文章，只出现 🏠、✅、📩，属于功能覆盖不足，即使总数达到旧规则也不能提交。不能把数据导航符号计作情绪表达，也不能让最后的私信符号代替中间的事项导航。
- 按独立信息项检查，不按自然段检查：收纳、厨房动线、材料选择、验收动作是不同事项，即使写在同一段中，也不能只用一个收纳或检查图标代表全部。多个同类柜体可归为一项，但不能把厨房或验收混进柜体组。无列表的仿写段落仍需在各独立事项的短语附近落实符号；原创内容中的并列事项按 `viral-layout-formatter` 分行扫读。
- 例如已有装修事项在原创模式中可以呈现为 `🗄️ 柜体收纳……\n🍳 厨房动线……\n🪵 已有板材信息……\n💧 已有防水试验信息……\n🔍 已有验收记录……`；省略号处只放当前证据支持的内容，`\n` 在成稿中必须是真实换行。若把这些事项重新并成材料长段，只留段末一个 🔍，即使其他位置已有很多 Emoji，也判为覆盖未完成；应在本次调用内修正后再提交。
- 参考蓝图的 `emoji_pattern` 是可观察的排布参考，不是数量上限，也不是使用许可。参考少表情或无表情时，仍按当前材料补齐适用功能；保留冻结的结构顺序、段落节奏与列表类型。`list_pattern.type=none` 时在原有事实短语旁加入符号，不擅自改成清单；已有数据列表或事项列表时逐行落实导航。
- 标题可以使用一个与主题或情绪直接相关的 emoji，通常放在开头、结尾或自然停顿处。只有在不破坏标题公式槽位、关键词识别和长度限制时才使用。
- 正文可在开头钩子、句中情绪、转折、重点提醒、结果确认或互动收尾处使用 emoji。叙事内容不要机械地每段固定放在开头，也不得全部放在句号前或段落末尾；表情应紧贴所修饰的场景、金额、转折、确认或互动词组。报价单、材料清单、步骤和改造项目允许按参考连续多行使用 emoji 作为行首导航，同类符号也可以连续重复。
- emoji 必须承担明确语义，例如场景、提醒、确认、情绪或行动提示。选择应贴合文章内容和人设，不能只为装饰或模仿热闹感。
- 可以参考爆款样例中 emoji 的位置和功能，但不得照搬样例原句、事实或整套符号序列；数量随当前适用的语义锚点调整。
- 必须区分叙事分散型、清单连续型和混合型。参考在句中或句末使用 emoji 时，不得统一移动到段首或段末；“每段最后一个”不是分散穿插。参考在报价或项目清单中连续使用时，不得为了“克制”而删成一个符号。
- 不用数字 emoji、键帽数字或 emoji 代替价格、面积、时间、步骤编号、产品参数和 Evidence ID；所有事实数字仍受数字白名单与证据约束。
- 不用 emoji 替换品牌名、产品名、公式关键槽位、风险提示或合规表述，也不得用它弱化免责声明和必要边界。
- 标题和正文中的 emoji 应保持同一种表达气质。同一语义锚点通常使用一个符号，避免连续表情串；最终只删除无关或重复的符号，不得以“克制”“去 AI 味”为由删除已经承担情绪表达或信息导航的符号。

## 避免机械表达

- 避免连续使用“首先、其次、最后”“值得注意的是”“总而言之”等模板连接词。
- 不要把正文公式或写作提纲翻译成读者可见的提示语。删除“旧况很典型：”“这套案子的关键数据先摊开：”“先说背景：”“再看过程：”“最后看结果：”等报幕式开头，直接进入具体场景、事实或人物感受。
- 避免空泛口号、同义反复、整齐划一的段落结构、连续感叹号和没有对象的夸张形容词。
- 避免每段都使用相同的开头、句式、设问和总结方式。
- 不要为了显得亲切而堆叠网络用语、方言、emoji 或过度口语化表达。
- 不要展示提示词、分析过程、修改痕迹或“作为 AI”等元话语。

## 封禁词替换

- 在 `evidence_bundle` 中查找 `metadata.rule_kind=forbidden_replacement_map` 的平台规则 Evidence。每次都从其 `value` 读取“问题词—常用表达方式”映射；不得凭记忆补充候选，也不得在 Skill 中固化具体问题词和替换词。
- 先写完标题和正文，再按问题词长度从长到短扫描，避免短词先替换后破坏较长词组。英文问题词按表格中的大小写分别处理；不得把表中两个独立词条擅自合并。
- 命中问题词且存在多个候选表达时，结合原句语义、词性、语气和相邻文字选择一个最自然的候选。不能机械地永远取第一个、不能把多个候选串在一起，也不能为了规避检查改变价格、品牌、服务范围、事实或承诺。
- 候选包含 Emoji、拆字或谐音表达时，仍需保证整句可读并符合渠道语境；它不计入爆款结构的 Emoji 数量要求，也不能代替本来承担情绪或信息导航功能的 Emoji。
- 命中问题词但候选列表为空时，不得删除问题词后留下残句，也不得发明表外替代词。应在不改变事实的前提下重写整句，使该概念不再需要出现；无法做到时不得提交成品。
- 替换完成后重新扫描最终标题、正文和话题。任何表内问题词仍然出现，或替换后语义、语法不通，成品均不合格；必须修正后再提交。成品中不得解释词表、替换动作或审核过程。

## 成品门槛

- 先按公式完成内容，再静默做一次“读者视角改写”。公式决定信息顺序，但公式名称、段落任务和写作步骤不得出现在成品里。
- 逐段检查开头：如果一句话只是在宣布“下面要讲什么”，删除它，让该段直接从人物、动作、冲突、数据或具体判断开始。
- 相邻段落不得使用相同的语法骨架开场；连续出现概括句时，将其中至少一段改为具体场景或自然承接。
- 出现“旧况很典型”“关键数据先摊开”“先说背景”“再看过程”“最后看结果”“下面来说”“接下来看看”等元话术时，成品不合格，必须在提交前改写。
- “满足公式”不等于“表达自然”。即使事实、结构和 Evidence ID 都正确，只要读起来像提纲填充或审核报告，就不能提交。

## 事实与结构边界

- 不得新增、修改或删除事实、价格、参数、数字、结果、承诺、案例、身份和 Evidence ID。
- 不得虚构“我亲自做过”“客户告诉我”“我们实测发现”等亲历、证言或业务经历；只有证据和人设资料明确支持时才能表达。
- 必须保持已锁定的创作手法、标题公式、正文公式和大纲结构。人味优化只改变措辞、语气、节奏和情绪表达，不改变业务逻辑。
- 正文事实只能来自允许用于标题或正文的冻结证据；`style_reference` 只可参考结构、节奏、互动方式和 emoji 模式，不可复制原句或引用其中事实。
- `paragraph_evidence` 必须继续准确对应相关段落，不得为了表达效果扩大证据含义。
- 必须遵守渠道规范、人设禁用表达、合规词库和封禁词处理要求。
- 人设表达与事实、合规或锁定公式冲突时，以事实、合规和锁定公式为准。

## 提交前自检

- 通读标题和正文，确认像同一个真实的人在同一场景中自然表达。
- 检查情绪表达是否能在 `content_brief`、人设资料或冻结证据中找到依据。
- 删除虚构亲历、虚假评价、无证据承诺和刻意煽情。
- 打散重复句式和过于整齐的模板节奏，但不破坏公式要求。
- 删除用于解释文章结构、公式步骤或段落任务的元话术，让每段直接承接上一段的真实场景和信息。
- 检查 emoji 是否与相邻文字语义一致，位置是否保持参考的布局节奏且覆盖当前适用功能。叙事分散型逐个记录“表情—相邻语义锨点—相对位置”，若全部落在段首或段末，必须重新穿插后才能提交；同时确认没有破坏标题公式、正文结构或数字证据约束。
- 完成 `humanizer-zh` 后再次检查最终正文的功能覆盖：实际存在的情绪、人设判断、数据类别、事项列表、提醒和互动是否各有恰当表达；指出遗漏的具体词组或条目并就地补齐，不能只检查 Emoji 总数。无依据的情感、不存在的列表和明确禁用的渠道标记为不适用。
- 确认标题、正文、话题与人设语气一致，事实和 Evidence ID 未发生变化。
- 只按节点要求提交 `GeneratedContentResultV1`，不要附加解释。

爆款仿写模式下，本 Skill 优化措辞并补齐语义 Emoji，不得把 `viral-structure-rewriter` 已落实的标题钩子、段落层级、情绪推进、互动方式或真实 Emoji 改写成平铺的企业案例说明，也不得把 `viral-layout-formatter` 已拆分的短段落、数据块、条目和互动收尾重新合成长段；`•`、`·`、编号和分隔线不能替代参考蓝图要求的 Emoji。

提交前检查最终 `body` 本身。信息块和空行由原创大纲或冻结仿写蓝图决定，不设置固定四处双换行或固定段落数。结构映射、排版、自然化编辑与本 Skill 共用一次最终自检；发现明确问题就地修正，禁止重复建立映射表、无限重写。事实、渠道限制和锁定结构优先，Emoji 只优化表达，不能改变或覆盖这些要求。服务端校验后的修正必须围绕返回的问题，受节点剩余调用额度限制。

## 创作类型的组合优先级

创作类型由 content_brief.content_type_code 与锁定 strategy_snapshot 确定，不能在正文中改成别的类型。先按 direction_blueprint 的层级、组别、组数写作，再在各层内部借鉴同类型爆款的语气和排版。任何参考蓝图都不能覆盖类型表规定的层级与词组组合。数据不足时明确报缺，不能编造人设、证据或转化承诺来凑表中数量。收到 CREATION_TYPE_ALIGNMENT 或 COMPOSITION_ALIGNMENT 阻断时按该类型的实际要求回修，不再受仅表情或仅首尾文字锁限制。

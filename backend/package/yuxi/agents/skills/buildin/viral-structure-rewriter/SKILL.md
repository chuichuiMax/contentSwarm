# 爆款结构仿写

## 创作类型与组合约束

前端选定的创作类型是硬约束。策略候选中的 direction_code 非空时，只能使用该类型及其公式候选、direction_blueprint 层级和词组组合，不得因为原文更像其他类型而改方向。装修参考卡的 content_type_code 必须与策略方向一致；同属价格营销不代表项目单价、单价+面积、工种总价、人工+辅材可以互换。

所选类型表规定的信息层顺序、组别、组数优先于爆款蓝图；参考蓝图只在本行组合允许的范围内指导钩子、段落节奏和排版。不得以“服从冻结爆款蓝图”为由省略所选类型的层级或添加禁止的层。无同类型参考时明确报缺，不降级选其他类型；业务资料缺失时指出缺失，不虚构事实凑词组数量。


仅在 `payload.runtime_config_snapshot.creation_mode=viral_rewrite` 时执行；原创模式保持静默，不改变正常原创流程。

## 一、读取唯一参考

1. 在 `payload.evidence_bundle.items` 中找到唯一同时满足以下条件的证据：
   - `allowed_usage` 包含 `style_reference`
   - `metadata.material_type=viral_example`
   - `metadata.usage_mode=structure_reference_only`
   - `metadata.selected_reference=true`
2. 完整读取该证据的 `metadata.reference_blueprint`，不得只读取 `selection_reason` 或摘要。
3. 爆款只决定“怎么写”；标题和正文里的品牌、价格、数字、案例、产品、客户与结果只能来自允许用于 `title` 或 `body` 的真实 Evidence。
4. 同时读取 `metadata.selection_basis`，确认选中的参考是按当前 `content_brief` 非空变量选择且 `structure_fillability.unfilled_required_slots` 为空。若缺失或仍有不可填充槽位，不得自行补造内容后继续生成。
5. 回修轮次还必须读取 `payload.validation_report`、`payload.review_report`、`payload.selected_title`、`payload.content_outline` 和 `payload.content_draft`；它们是上一轮被阻断内容与定点修改要求，不得只重新执行首次生成流程。

## 二、强制生成仿写结构映射表

写标题、大纲或正文前，必须先在内部生成完整的“仿写结构映射表”。映射表不得省略、不得用一段概述代替，也不要作为文章正文输出给用户。

| 映射项 | 参考结构 | 当前内容的实现方案 | 使用的 Evidence ID | 验收信号 |
| --- | --- | --- | --- | --- |
| 标题模式 | `title_pattern` + `title_slot_sequence` | 每个参考槽位映射到当前输入字段；无证据槽位须删除或改成非事实表达 | 真实事实证据 | 标题结构可识别且每个事实都来自当前输入 |
| 开头钩子 | `opening_hook` | 第一段具体写法 | 真实事实证据或无事实断言的场景 | 前两句即可识别 |
| 叙事顺序 | `content_block_sequence` + `narrative_structure` | 每个真实结构节点对应的大纲和正文信息块 | 每段真实事实证据 | 顺序完整且一一对应 |
| 列表结构 | `list_pattern` | 按参考真实类型决定无列表、编号、Emoji、项目符号或混合列表 | 可为空 | 类型、位置和条目节奏与参考一致 |
| 段落节奏 | `paragraph_rhythm` | 按参考实际短句、长段、列表、信息块和停顿方式映射 | 可为空 | 正文排版可直接识别 |
| 情绪曲线 | `emotion_curve` | 各段情绪状态及转折句 | 可为空 | 至少存在一次明确推进或转折 |
| Emoji 模式 | `emoji_pattern` | 判断叙事分散型、清单连续型或混合型，并映射真实 Emoji 的相对位置、功能和密度 | 可为空 | Emoji 分布方式与参考一致，且正文中可直接看到真实 Emoji |
| 互动方式 | `interaction_style` | 结尾的提问或回应机制 | 需要事实时引用真实证据 | 最后一段可直接识别 |

完成映射表后才可以写作，并严格按表生成标题、大纲和正文。每一个结构节点都必须有当前业务信息承接。没有真实业务证据可填的普通表达节点，可改写为不含事实断言的场景或观点表达；决定参考成立的核心数据块、结果块或清单无法承接时，说明该参考选择不合格，禁止复制爆款事实或用空泛内容补位。

标题必须先完成“参考槽位→当前变量→Evidence ID”的逐槽绑定。标题中的面积、预算、户型、城市、工期、结果、完工和结算状态必须与当前输入原意一致；“有预算”不等于“预算内完工”，“预计工期”不等于“已经完工”，“方案结果”不等于“最终结算结果”。没有相应证据时不得使用“搞定、完工、省下、落地、最终费用”等暗示已完成或已结算的表达。

报价明细、分项价格或工价清单结构可以用当前知识库的适用标准单价填充，明确以“标准单价参考”呈现；不要求有工程量、分项小计或与另列的项目总预算加总一致。保留清单结构，展示实际已有的价格项目，不虚构缺失类别；只有明确依赖实际成交、结算或节省结果的核心内容才需要相应项目证据。

写作过程中不得擅自把映射表中的短句、列表、情绪推进、Emoji 或互动方式改成长段说明文。

## 三、植入真实 Emoji

按 `content-human-expression` 的语义覆盖规则落实 Emoji。`emoji_pattern` 描述参考的符号分布，不是成稿的数量上限或使用许可；参考没有或只有少数符号时，仍根据当前材料的情绪、人设、数据与事项补齐适用功能。渠道或用户明确禁用时不用，专业人设采用更准确的符号，不以职业身份作为删除理由。

- **叙事分散型**：保留参考在句中或句末的自然停顿，按当前语义安排表情；叙事锚点至少包含一个非段末落点，不得统一放在自然段开头或结尾。
- **清单连续型**：报价或项目清单中可以连续使用与条目匹配的符号；面积、预算、时间和不同事项分别导航，不用一个表情代替整组独立信息。
- **混合型**：叙事段表达已有的共鸣、判断、情感变化，清单段逐项导航。数据图标不能代替情绪表情，互动符号不能代替正文中的功能。

先在内部记录“结构块—相邻语义锨点—功能—相对位置”，按当前内容补齐，再核对冻结的 `content_block_sequence`、`paragraph_rhythm`、`list_pattern`。补表情不等于新增或重排结构：参考没有列表时，在原有短语旁添加符号；参考已有列表时保留类型、顺序和独立条目。普通项目符号和编号不计入 Emoji。

不能仅因正文已有三个表情就判定通过。正文实际出现的痛点、情感变化、数据类别、事项列表、提醒与互动都应有合适的表达；不适用的功能无需硬加，不能为表情虚构事实或情绪。功能覆盖完成后删除无关、重复的表情串，不退回只在开头或结尾装饰的版本。

## 四、保留可感知的爆款结构

仿写不是只保留“痛点—方案—结果”的通用信息顺序。必须让读者能感知以下特征：

- 标题沿用参考的组合方式、点击理由和情绪力度，同时服从锁定标题公式和渠道长度。
- 第一段沿用参考的钩子类型，例如人群召唤、强场景、疑问、反差或结果前置；不得退化成报告式背景介绍。
- 参考使用数据卡、短句、分点、清单或一问一答时，正文也要采用相近的信息呈现方式，而不是全部改成长段说明文。
- 列表形式完全服从 `list_pattern`：仅当参考真实采用编号列表时才使用编号，并按蓝图记录的出现位置和条目节奏实现；参考采用 Emoji 清单、项目符号、连续叙事或混合结构时，禁止擅自改成 `1–4` 或其他固定编号清单。
- 参考通过“问题—动作—变化”形成节奏时，每个核心问题都应对应具体解决动作和可验证结果。
- 保留参考的情绪推进强度，但根据品牌人设调整措辞，不能把鲜活表达统一润色成企业介绍。
- Emoji 按当前材料的语义功能覆盖，并保留参考的布局节奏；专业或严肃人设调整符号气质，不得删除必要的情绪表达和数据、事项导航。
- 结尾沿用参考的互动机制，但必须遵守渠道 CTA 和合规规则。

## 五、禁止事项

- 禁止复制或近义改写爆款原句。
- 禁止复用爆款中的城市、面积、预算、价格、工期、品牌、客户身份、案例结果和商业承诺。
- 禁止只把业务名词替换进去而保留原文句子骨架。
- 禁止把结构蓝图写成读者可见的“第一步、第二步、按照某公式”等元话术。
- 禁止因为 `content-human-expression` 润色而丢失已经映射好的钩子、列表、节奏、情绪曲线和互动结构。
- 禁止用 `•`、`·`、数字编号或分隔线冒充 Emoji 植入。
- 禁止在参考含多个 Emoji 时只保留一个开头 Emoji。
- 禁止不判断 `emoji_pattern` 的分布模式，就把所有 Emoji 统一放在自然段开头；报价、材料、步骤等参考清单允许连续行首 Emoji，不受此限制。
- 禁止叙事分散型把所有 Emoji 统一放在句号前或自然段末尾；“每段最后一个”仍属于机械堆放，不算语义穿插。
- 禁止把“1–4 编号清单、固定五段、四个空行、三个改造项”等某篇样例特征当成所有爆款的通用要求。

## 六、定点回修

只要 `validation_report` 或 `review_report` 为 `blocked`，先建立“问题位置—阻断 code—上一轮原文—修改动作—验收信号”的回修清单，再修改上一轮输出：

- 标题事实或公式被阻断时，必须重新绑定当前输入变量，产出与上一轮不同且消除问题的新标题；禁止原样再次提交。
- 结构被阻断时，只修复蓝图中真实存在但未落实的 `content_block_sequence`、`list_pattern`、节奏或互动特征；审核建议与冻结蓝图冲突时，以冻结蓝图为准，不执行通用编号或固定段落要求。Emoji 功能遗漏按当前语义就地补齐，不以参考表情少为由拒绝回修。
- 回修后逐项对照所有阻断项复核；仍命中同一问题时不得提交结果。

## 七、提交前逐项验收

写完后必须重新读取“仿写结构映射表”和最终文稿，逐项给出内部验收结果。以下五项全部为硬门槛：

| 验收项 | 通过条件 |
| --- | --- |
| 开头 | 前两句落实 `opening_hook`，不是报告式背景介绍 |
| 节奏 | 最终正文实际保留映射表约定的段落、列表、信息块或停顿方式；列表类型与 `list_pattern` 一致 |
| 情绪 | 情绪状态随叙事推进，至少有一次可识别的转折或增强 |
| Emoji | 按当前材料覆盖适用的情绪、人设、数据与事项导航功能，并匹配叙事分散型、清单连续型或混合型分布；不能以三个符号作为验收目标，每个符号都有相邻语义锨点；普通项目符号和编号不计入 |
| 互动 | 最后一段落实 `interaction_style`，且符合渠道 CTA 与合规要求 |

初稿完成后仅进行一次结构自检并修正明确问题，禁止在当前调用内无限重写。之后提交 `GeneratedContentResultV1` 交由服务端验证，失败时按具体反馈定点修正；修正与连接重试共用节点调用额度，不放宽任何事实或结构校验。

五项通过后，再确认标题逐槽对应 `title_pattern` 和当前输入变量、大纲逐项覆盖 `content_block_sequence` 与 `narrative_structure`、所有事实和数字来自允许用于标题或正文的 Evidence。最后执行反退化检查：删除参考爆款后，文章仍应能看出采用了同类结构；如果只剩通用案例说明稿，在本次自检中修正偏离的段落；不得重新规划整篇或反复自检。
